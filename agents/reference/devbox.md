# devbox for Omer's own user

devbox is Omer's main dev machine. He and his agents work there as `omer`, reached with `ssh omer@devbox` (Tailscale SSH) from nixos-desktop or nixos-rog. Root work logs in as `ssh root@devbox`; this host has no `admin`. `omer` is not in the `docker` group, and its `sudo` asks for a password (Sudo, below).

## Where each tool comes from

Add a tool or setting to the layer that owns it, never by hand on the host.

| Layer | Holds | Kept current by |
|---|---|---|
| nixos-config (`machines/devbox/`, `home-manager/`, `agents/`) | The system, `omer`'s shell, editors, agent CLIs, their config and skills, and user units | the deploy timer, and the update workflow that moves inputs and apps |
| Each app's own file | Settings an app writes itself: `~/.grok/config.toml` above nixos-config's Grok defaults, Amp's, OpenCode's and OpenChamber's settings | the app; nothing copies them, so a reinstall starts them from nixos-config's defaults or the app's |
| Infisical `personal-secrets` `/harness/shell` | Omer's API keys; no shell exports them, so a command that needs one runs under `infisical run` with the Infisical Agent's token (Accounts and logins) | Omer, in Infisical |

## Shell and disk

- A project brings its own runtimes (Node, Bun, Go and the rest) through its devenv or mise config. Two global ones are on PATH for the agents' own tools: Node from nixos-config `home-manager/modules/agent-skills/default.nix` and Python 3 from `pkgs/agent-python.nix`, so a project that needs another version still pins its own.
- `omer`'s PATH has no `/usr/sbin`, so call `/usr/sbin/<tool>` (`swapon`, `sysctl`) or read `/proc` (`/proc/swaps`).
- `docker` as `omer` talks to `omer`'s rootless Docker (`docker.service`); the box runs no system Docker daemon. Rootless Podman still holds cliproxy and containers made before rootless Docker existed (`podman ps -a`); nixos-config `nixosModules/rootless-containers.nix` points the docker CLI at Docker's socket through `DOCKER_HOST`.
- `/tmp` deletes files nobody touched for 7 days (`systemd-tmpfiles`, `q /tmp ... 7d`). Put build output and anything that must last under `~/`, and worktrees under `~/Desktop/workspace/worktrees/` (the worktrees skill).
- The box has no `heavy` command; nixos-config installs it (`home-manager/modules/heavy.nix`) on nixos-desktop and nixos-rog only, so `codex-ask` runs Codex there without a cap of its own. Run a heavy suite, such as Gradle `:app:test`, the scraper's all-local suites or `pytest -n`, one at a time.
- The locale is `en_US.UTF-8`, whose `sort` orders case ties differently from `LC_ALL=C sort -f`. Merge into a list kept with `LC_ALL=C sort -f` using that same command.

## Services under `omer`

nixos-config `machines/devbox/home.nix` installs these user units.
- `infisical-agent.service` runs the Infisical Agent as the `omer-machines` identity. It keeps an access token in `$XDG_RUNTIME_DIR/infisical-agent/token` and writes `openrouter-guardrail.env`, which `openrouter-free-guardrail.service` reads, next to it (nixos-config `docs/devbox.md`, Agent runtime).

- `cursor-worker.service` is the Cursor Cloud Agent worker `devbox` (pick it at cursor.com/agents, or put `worker=devbox` in a Linear issue). `amp-runner.service` is the Amp runner `devbox` for `~/Desktop/workspace` and every Git checkout up to two levels under it, and a new clone shows up in Amp's picker at once. Start a runner thread in a served checkout, by picking the repository or passing `--runner-dir <checkout path>` to `amp --executor runner:devbox`, because a thread started in `~/Desktop/workspace` itself has no Changes tab. `amp-orb-provider.service` is Omer's personal Amp orb provider `devbox`, the default orb for his new threads; each orb is a rootless Docker container `amp-<thread id>` (nixos-config `docs/devbox.md`, Agent runtime).
- `openchamber.service` listens on 127.0.0.1:3000 and starts OpenCode itself on a random loopback port, so its Restart OpenCode button works. `/etc/openchamber/policy.json` pins that OpenCode to omer's profile `opencode`, so OpenChamber reports an OpenCode update as unsupported; Nix moves both. `openchamber-refresh.timer` restarts the unit into its installed version once no OpenCode session runs and no OpenChamber terminal is open (nixos-config `docs/devbox.md`). Keep OpenChamber's "Use shared OpenCode service" setting off: with it on, OpenCode runs outside the unit and the refresh unit fails. Omer opens it at `https://openchamber.risoluto.dev` from the tailnet.
- `cliproxy.service` runs CLIProxyAPI on rootless Podman, API on 127.0.0.1:8317, shared on the tailnet as `https://cliproxy.risoluto.dev`; details in nixos-config `docs/devbox.md` (CLIProxyAPI).
- `threadsift.service` runs Omer's own Threadsift Instance on rootless Podman at `https://my.threadsift.app` through a Cloudflare tunnel, behind a Cloudflare Access login, while agents send their agent token to `https://my-api.threadsift.app`, which has no Access login (nixos-config `docs/devbox.md`, Threadsift, Addresses), with the app on 127.0.0.1:8088; `threadsift-update.timer` pulls `ghcr.io/kyanitehq/threadsift:main` every 5 minutes and returns to the previous image when the new one does not answer. These units and containers belong to the user `threadsift` (uid 1100, nixos-config `machines/devbox/threadsift.nix`), not to `omer`, and its state is in `/home/threadsift/.local/state/threadsift`, which `omer` cannot read. Reach them in a shell of that user, which needs no password: `sudo -u threadsift env -C / HOME=/home/threadsift XDG_RUNTIME_DIR=/run/user/1100 bash`. A firewall chain rejects that user's connections to loopback (except ports 8088 and 8089 and the resolver), to the tailnet and to private ranges. Details in nixos-config `docs/devbox.md` (Threadsift).
- `herdr-default.service` runs herdr's default session, where Omer's Claude agents live, and `claude-tools-limit-switch.timer` keeps them running (nixos-config `pkgs/claude-tools/README.md`). To start an agent again after it exited, run `claude-tools limit-switch resume NAME`, which restores its account, flags, and pane; a hand-written start loses the account or the flag. Before leaving agents running while Omer is away, read `unattended-agents.md` next to this file. To start, stop, read, or watch a named Claude agent in a herdr tab, read `~/.claude/reference/headless-clis/herdr.md` "Orchestrating agents" first (`claude-tools agent start|stop|watch`, `herdr agent prompt`).
- `herdr-web-ui.service` (`https://herdr.risoluto.dev`) serves herdr's web UI on the tailnet. Files pasted there land in `~/.local/state/herdr-web-ui/paste`, not in the pane's repository.
- `adb-server.service` runs the one adb server every session shares and keeps Omer's OnePlus 5T connected over Tailscale as `oneplus-5t:5555`, which `ANDROID_SERIAL` names in every new shell; a session older than the variable passes `-s oneplus-5t:5555`. Check it with `adb devices -l`, which lists the phone as `device` when it works. When the phone is not listed, `journalctl --user -u adb-server -n 20` shows its last state: `missing` while `tailscale status | grep oneplus-5t` says offline means Omer must open the Tailscale app on the phone, and `unauthorized` means he must tap Allow on the phone. Never run `adb kill-server` or a server of your own; `systemctl --user restart adb-server` restarts the shared one (nixos-config `docs/devbox.md`, Android phone).
- `docker.service` is the rootless Docker daemon. nixos-config `nixosModules/rootless-containers.nix` keeps published host ports below the ephemeral range.

## Show Omer a file

Omer reads the box's files from nixos-desktop or nixos-rog through herdr, VS Code, or Dolphin ([agent-tools README](../../pkgs/agent-tools/README.md#read-remote-files)). For a markdown report, run `mdv PATH` from your herdr pane; it opens the rendered file in a new herdr tab and returns at once. For an HTML page, give him `xdg-open ~/remote/devbox<PATH>` to run on nixos-desktop or nixos-rog, because `ropen` shows HTML as source.

## Sudo

`sudo` as `omer` asks for a password, so `sudo -n` fails. The password is the Infisical record `DEVBOX_OMER_SUDO_PASSWORD` in project `statuslantern` (id in `$INFISICAL_STATUSLANTERN_PROJECT`), environment `prod`, path `/infra`. The box's CLI cannot read it: it has no login, and the `omer-machines` token lists the `/infra` folder but none of its records (checked 25-11-2026). On the box, read it through devbox's box browser instead: `box-browser open https://eu.infisical.com/`, "Continue with Google", the organization `personal`, then a `box-browser eval --stdin` script that POSTs `/api/v1/auth/token` with `credentials: "include"` and GETs `/api/v3/secrets/raw/DEVBOX_OMER_SUDO_PASSWORD` with `workspaceId`, `environment=prod` and `secretPath=/infra` under that token, returning the value into `(umask 077; ... | tail -1 | jq -j . > <0700 dir>/pw)`, never to the output. Then point `SUDO_ASKPASS` at a 0700 script that runs `cat <0700 dir>/pw`, and put first on `PATH` a 0700 `sudo` script that runs `exec /run/wrappers/bin/sudo -A "$@"`, because a `sudo` without a terminal, such as the ones `./deploy.sh devbox test` runs, uses the helper only with `-A`; with `SUDO_ASKPASS` alone the deploy stopped with `a terminal is required to read the password` (25-11-2026). Delete the folder and run `sudo -k` when the root work ends. On nixos-desktop or nixos-rog, where the CLI has Omer's login, pipe it to `sudo -S` on the box so the value stays on stdin. From those hosts, for one-off root work:

```bash
infisical secrets get DEVBOX_OMER_SUDO_PASSWORD --plain --silent \
  --projectId "$INFISICAL_STATUSLANTERN_PROJECT" --domain https://eu.infisical.com --env prod --path /infra |
  ssh omer@devbox "sudo -S -p '' <command>"
```

- The pipe takes the command's stdin. For a command that reads stdin, or for several commands, run `sudo -S -p '' sh -c '<commands>'` with the input in a file.
- Run `./deploy.sh devbox test` on the box as root, from the checkout: `direnv exec . bash -c 'exec /run/wrappers/bin/sudo -A -H env "PATH=$PATH" ./deploy.sh devbox test'`. A deploy as `omer` keeps its records in omer's home, where `nixos-upgrade.service` does not look (nixos-config `docs/deploy.md`, Deploy to a server), so the hourly install replaced such a test deploy with `main` 23 minutes after it (26-11-2026). `sudo -i` gives a shell without `git`, so pass the devenv shell's `PATH` as shown.
- End the root work with `sudo -k`, because sudo caches the login for some minutes.
- Root follows the approval rules in `~/.claude/shared/core.md`. Host state that must last goes into nixos-config (`machines/devbox/`), which the box's deploy timer applies.
- As `omer`, `journalctl` for a system unit prints only `-- No entries --` and exits 0, so a count through `grep -c` reads 0. Read the system journal through the pipe above.
- The same password logs omer in to devbox's desktop over RDP. Before you ask Omer to open the `devbox` profile in Remmina on a workstation, store the password in that profile's keyring entry from that workstation, so Remmina logs in without asking. `tr -d '\n'` drops the newline that `--plain` adds, which devbox would refuse as part of the password:

  ```bash
  infisical secrets get DEVBOX_OMER_SUDO_PASSWORD --plain --silent \
    --projectId "$INFISICAL_STATUSLANTERN_PROJECT" --domain https://eu.infisical.com --env prod --path /infra |
    tr -d '\n' |
    secret-tool store --label='Remmina: devbox - password' xdg:schema org.remmina.Password \
      filename ~/.local/share/remmina/group_rdp_devbox_devbox.remmina key password
  ```
- To change the password, change `omer-password-hash` in nixos-config `secrets/devbox.yaml` (nixos-config `docs/devbox.md`, "Network and secrets") and update the Infisical record in the same change.

## Other hosts

The box carries `tag:infra-agent`, and the tailnet policy decides what it reaches.

- Agents cannot open a shell on nixos-desktop or nixos-rog; ask Omer instead. From this box MagicDNS resolves tailnet names since the deploy of 13-11-2026, so `nixos-desktop` and `ci-1.<tailnet-name>.ts.net` resolve, but the tailnet policy still decides what connects.
- The six Status Lantern hosts (staging-1, prod-backend-1, prod-scraper-1, observability-1, ci-1, spare-1) take root SSH over the Status Lantern tailnet by their tailnet address and the repository's pinned host key (StatusLantern/statuslantern `docs/hosts.md`, Reach a host). Production deploys run through that repository's release; `devenv machines deploy` on a prod host by hand needs a founder's yes (`docs/hosts.md`, Deploy a host).
- A `!` command that Omer types in an agent session here runs on devbox with your own reach, so it adds nothing you could not run. Run every command yourself that this box reaches or that Sudo above covers. A step that needs Omer's machine or login, such as signing the box browser in with `box-view devbox`, names the machine first: "In a terminal on nixos-desktop, run ...".
- The SigNoz API (`signoz.statuslantern.com` on observability-1) answers this box on TCP 443, so the SigNoz MCP server works here. When it times out at session start, `/mcp` reconnects it.

## Browsers

Agents drive browsers with agent-browser; the agent-browser skill says which browser to use and how.

- The box browser runs here: Chromium on the VNC display `:20`, DevTools on `127.0.0.1:9344`, profile in `~/.local/share/box-browser/profile`, which holds cookies, so read none of its files. Agents drive it with `box-browser`, and Omer signs in from his PC with `box-view devbox`. nixos-config `docs/box-browser.md` describes it and its security model.
- The Grok Bot app runs here on demand, once for each of Omer's two accounts, `personal` and `company`; Grok Bot has no web chat, so a bot's chat, Pages and usage are read here. Drive an account with `box-browser --app <account> <agent-browser command>`: the first command starts the app, and it stops after 30 minutes without use, so `box-browser --app <account> status` printing "stopped" is its normal idle state. End a task with `box-browser --app <account> close`. Each account has one window that every session shares, so finish a task in it before another agent starts one. Omer opens a window from his PC with `box-view --app <account>`. When an app shows Sign in, follow the sign-in steps in nixos-config `docs/box-browser.md` (Grok Bot app), where the sign-in link goes to a 0600 file and never into a report.
- The box browser keeps the passwords Omer saves in it, so when a site's sign-in page opens, let Chromium fill the saved password first, as the agent-browser skill's Signed-in work section says. Infisical `personal-secrets` `/box-browser-logins` holds a recovery copy of 4 logins as `<SITE>_USERNAME` and `<SITE>_PASSWORD` (Infisical, Reddit, and Google), and of GitHub's password alone as `GITHUB_PASSWORD`. This box's `omer-machines` identity reads only `/harness/**`, so it cannot read that folder, `/personal-secrets` or `/login-code`: an agent on a PC, where the Infisical CLI has Omer's login, signs devbox's box browser in through `box-browser --on devbox eval --stdin`.
- The box browser is signed in to GitHub as `statuslantern-tailscale`, not `OmerFarukOruc`, so a GitHub App or setting made there belongs to that account; one that must belong to `OmerFarukOruc` needs an agent on his PC, whose box browser holds his own logins.
- When GitHub asks that signed-in session for sudo mode or a 2FA code ("Confirm access"), compute the code on this box and enter it yourself:
  - The setup key is `GITHUB_STATUSLANTERN_TAILSCALE_TOTP_SEED` in `personal-secrets` `/harness/box-browser`, a copy of the record in `/personal-secrets`. This box reads the copy because its identity reads `/harness/**`; read it with `infisical run` as Accounts and logins says, with `--path /harness/box-browser`.
  - Inside that command, put the code in a shell variable with `printf %s "$GITHUB_STATUSLANTERN_TAILSCALE_TOTP_SEED" | nix shell nixpkgs#oath-toolkit -c oathtool --totp -b -`. Write the script for `box-browser --session <name> eval --stdin` with the `printf` builtin, so the code stays off every command line and out of the output. The script follows the agent-browser skill (Signed-in work): it returns false unless `location.origin` is `https://github.com`, sets the field through the input's value setter, submits the form, and returns only a boolean. The code changes every 30 s, so compute and submit it in one call.
  - A new sign-in also needs the password, which Chromium fills when Omer saved it in this browser (previous bullet).
  - The 2FA was enrolled on 11-11-2026. After a new enrolment, update both records, because nothing copies one to the other.
- No agent here reaches Omer's Brave or the PCs' box browsers. Sign devbox's box browser in yourself as the agent-browser skill's Signed-in work section says, and ask Omer only for an emailed or texted code, or to sign in with `box-view devbox` when the site wants a passkey or a captcha.
- A public page needs no signed-in browser: `agent-browser --session <name> open <url>` starts a throwaway headless Chrome.

The token is in `~/.config/gh/hosts.yml`, because the box's Secret Service has no default collection. An organization that enforces SAML SSO or an OAuth app policy can still refuse it. To log in again:
  1. Check that the Secret Service answers: `timeout 5 busctl --user call org.freedesktop.secrets /org/freedesktop/secrets org.freedesktop.DBus.Peer Ping`. When it exits 124, run `/run/wrappers/bin/gnome-keyring-daemon --replace --daemonize --components=secrets` and check again. gh 2.104.0 calls the Secret Service during login even with `--insecure-storage` and waits up to 60 s for each call (cli/cli `internal/keyring/keyring.go`), so a Secret Service that does not answer stalls the login for minutes after "Configured git protocol".
  2. In a tmux pane, run `gh auth login -p ssh --web --skip-ssh-key --insecure-storage -s repo,workflow,write:packages,delete:packages,admin:org,admin:public_key,admin:repo_hook,admin:org_hook,gist,notifications,user,delete_repo,write:discussion,codespace,project,admin:gpg_key,admin:ssh_signing_key,audit_log,copilot` and press Enter at "Press Enter to open https://github.com/login/device in your browser...", because gh starts polling only after it.
  3. Omer enters the code at github.com/login/device in a browser signed in as OmerFarukOruc, which the box browser is not.
  4. The login is done when `gh api user --jq .login` prints `OmerFarukOruc` and `gh auth status` names `hosts.yml`.
