# Readiness checks

Each row is the one statement of a rule the finished plan meets. The planner writes to
these rows while filling the template, then reads the plan as the executor will, cold,
and checks every row.

| Check | Pass when | Plan section |
| --- | --- | --- |
| Contract gap | Every interface, default, error, ordering, state owner, and compatibility choice the change needs is written down, and the Bounds line names the users, operators, concurrent writers, and how much failure is acceptable | Outcome, Decisions |
| Zero-context | Every decision, fact line, convention, command, `path::symbol`, and exemplar the planner used is in the plan; every edit and test names `path::symbol`, never "the relevant module". Implementation code left for the executor is not a gap | whole plan |
| TARGET | Each TARGET fence is one load-bearing construct (a signature, a JSON object, an error string, or a registry insert) with where it goes and what it replaces, at most one per Change step and six per plan; never a function body, test body, module, or document. Every other edit names `path::symbol` and an exemplar, plus each argument, annotation, or field the edit needs that the exemplar lacks | Slices |
| Pasted text | Every Change step that pastes or writes text, code or prose, is followed by a Change step that runs the repository's full pre-PR gate on the touched files, before any other edit, except the step that runs the Red proof, which ends on that run; no character count, no prediction of a gate's parser | Slices |
| Commands | The first command installs what a fresh worktree lacks; every command comes from the file that defines it, runs from a named working directory with watch mode off, and has an expectation that fails when zero tests are selected; Green names the test names or output lines expected; a timeout, wait, or retry count names its source or says `guess`; a command that holds `\|` sits in a fenced block under the table, because a table cell escapes the pipe and the executor copies the escape | Commands, Slices |
| Proof shape | Every Behavior line names its proof and the cases it drives: a command that runs the real program or system the way its caller does, or an existing test that already reaches the behavior; a low-risk local change names the existing check that proves it. A new isolated test appears only when Omer asked for it, in his message or the issue he wrote, or the repository's instructions require one for this change; the plan cites that request or file and heading, and the test extends the contract's owner test. A bug slice reproduces the bug through the real program and handles the tests as testing-discipline.md, Bug fixes, says. A feature that crosses components gets a medium or hard end-to-end scenario and an artifact: rerun command, captured result, pass condition. When the plan adds, edits, or deletes tests, fixes a bug, or claims end-to-end proof, the Final gate's review is the `code-reviewer` agent, or names testing-discipline.md in its prompt. Every slice has Red with its exact pre-change output, copied from a run at the pinned SHA or followed by NOT RUN, and Green with its expected output, and the step order produces that Red. The rules come from `~/.claude/shared/testing-discipline.md`, which wins wherever the two differ | Slices, Final gate |
| Proof aim | A Red that rejects input fails at the guard it targets, not at an earlier parse or permission check; when another mechanism can produce the same observable, the plan names it and adds a control run that differs only in the behavior under test; no proof asserts through a test double or a fabricated fixture | Slices |
| Slow proof | Every command in Green or the Final gate that takes minutes names its measured duration and host and runs its independent parts at once; a comparison of two runs excludes, by exact path or name pattern, only paths other processes change, and none the change reads or writes; a faster command with its host and expected output covers the same code and runs after a fix, before the full proof again | Slices, Final gate |
| Baseline | A failure that exists before the change stays in the plan as baseline evidence, with the comparison that shows no regression | Commands, Final gate |
| Unfalsifiable criterion | Every Behavior line names an observable result that can fail; none names an implementation | Slices |
| Coverage | Every requirement in Outcome has at least one Behavior line, and every slice serves a requirement; no requirement or Behavior line rests on a vague word such as fast, robust, or clean | Outcome, Slices |
| Touch set | Every path the slice forces (test, fixture, lockfile, generated file, routed document) is in its touch set | Slices |
| Callers | Every symbol a slice deletes, renames, or re-signs lists each path that references it, copied from a named search command's output, and each of those paths is in a touch set or named as unaffected with the reason; a caller list that would push the plan past the Length limit splits the change into batches, as planning-guide.md, Slice the work, says for a wide mechanical change | Current state, Slices |
| Slice independence | Each slice ships alone with CI green; each blockedBy edge names code the slice consumes or a file, fixture, or generated artifact both slices write; a producer slice and its consumer both write the exact signature: names, types, serialized fields, defaults, and error behavior | Slices |
| Boilerplate STOP | At least one stop condition names this plan's own risk, and the section keeps the template's stop report shape | Stop conditions |
| Placeholders | No `{{ }}`, angle-bracket cell outside the stop report shape or a pattern that Terms defines, such as `/<locale>/`, TBD, "handle edge cases", "similar to slice 2", or "as discussed"; no pointer at a conversation, an audit, or an un-inlined document; a Decision two slices share is written in both | whole plan |
| Secrets | Identifiers and credential types only (`order_id`, `*_hash`, "the API key in the `SERVICE_API_KEY` secret"); no secret value, token, or personal record; no tracker id in text the executor pastes into the repository | whole plan |
| Drift | The header names the full SHA and branch; every fact line is true at that SHA; the first Change step of each slice runs `git diff --stat <SHA> --` and `git status --short --` on every Current state and touch-set path, except a file that another in-flight branch edits, whose fact line gets a `grep` for its symbol instead; a document citation names path and heading, and a line only when that line is what changes | header, Current state |
| Sources | Every third-party surface has an official source with version and section, or the plan says `in-repo only` with the imports checked; every external fact in Decisions cites a Sources line; a surface with none is in Open decisions | Sources, Decisions |
| Judgment steps | Every step is an imperative, positive action, with a prohibition only as a guardrail paired with the action to take; every check is a command with its expected output; no step asks the executor to decide whether it succeeded or what to do next | Slices, Final gate |
| Manual check | A check no command can run names its owner, setup, exact actions, and pass condition, and stays NOT PROVEN until that owner observes it | Final gate |
| Out-of-scope creep | No step touches a path or behavior listed under Out of scope | Decisions, Slices |
| Operator steps | Every deployment or production activation carries an Operator line naming the step and its rollback | Slices |
| Length and format | At most 250 lines, and a plan for one to three slices usually runs 150 to 250; no code body, test body, or line-range excerpt; a line number appears only inside quoted command output; plain Markdown with headings no deeper than `###`, so Linear, GitHub, and a file render it the same | whole plan |

Grade each failed row with the severity and the class that the plan-review skill's
`findings.md` defines under Severity and Class (`~/.claude/skills/plan-review/findings.md`),
so the author's grade and the reviewer's verdict use one scale. Rewrite the plan until no
P0 to P2 fix remains. The author's pass then marks the plan DRAFT when only P3 findings
remain, and BLOCKED when a decision remains, named in Open decisions. Each P3 finding
accepted without an edit goes under `## Residual` with the row it fails, whatever the
readiness. READY says the plan can start; it says nothing about the implementation until
the Final gate is green.
